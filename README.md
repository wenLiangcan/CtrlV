# ^V

A small, native macOS clipboard history. Press **Control+V**, type to search, and use a previous copy. Built with SwiftUI, AppKit, and the system’s Liquid Glass — no web runtime or third-party dependencies.

## Run

Supports macOS 15 (Sequoia) or newer (using `NSGlassEffectView` on macOS 26+ and `NSVisualEffectView` on macOS 15).

```sh
./script/build_and_run.sh
```

The Codex **Run** action uses that same script. The optimized universal (`arm64` + `x86_64`) app is at `dist/^V.app` (internal executable/package name `ctrlv`). The script uses an available Developer ID Application or Apple Development signing identity to keep the app’s permission identity stable across rebuilds. Set `CTRLV_SIGNING_IDENTITY` to select a specific identity. Without one, the script warns and uses ad-hoc signing. Open the app directly or move it to Applications. It lives in the menu bar intentionally, without a Dock icon. The panel opens on user-initiated launch (staying hidden when launched automatically at login) and can be dismissed by Escape or clicking another window.

```sh
./script/build_and_run.sh --build   # Build the universal .app without launching
./script/build_and_run.sh --dmg     # Build the .app and package dist/^V.dmg
./script/package_dmg.sh             # Package dist/^V.dmg directly
./script/build_and_run.sh --verify  # Build, launch, and check the process
swift test --disable-sandbox
```

When sharing an ad-hoc-signed `.dmg` or `.app` to another Mac via AirDrop or browser download (without Apple Developer ID notarization), macOS Gatekeeper quarantines the file. On the target Mac, either choose **Open Anyway** in **System Settings → Privacy & Security**, or clear the quarantine attribute after copying to Applications:

```sh
xattr -dr com.apple.quarantine "/Applications/^V.app"
```

## Use

| Shortcut | Action |
| --- | --- |
| Control+V | Show / hide the clipboard panel |
| Up / Down | Select an item while keeping search focused |
| Return | Paste the selected item, or copy it when direct paste is unavailable |
| Command+1–9 | Use one of the first nine visible items |
| Command+F | Focus search |
| Command+P | Pin / unpin the selected item |
| Command+Delete | Remove the selected history item |
| Escape / Command+W | Dismiss |

Click a row to use it. Right-click for pinning and deletion. The options menu includes pause capture and clear unpinned history. Both the menu bar and panel options include **Start at Login**, which is off until you enable it. This uses macOS [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice) and reflects the system’s registration status. If macOS requires approval, choose **Approve in System Settings…**. Keep the app in a stable location (preferably Applications) before enabling it. Search matches text, content kind, and source app, ignoring case and accents.

For automatic pasting into the previous app, choose **Enable Direct Paste…** from the menu bar or panel options, then enable ^V in **System Settings → Privacy & Security → Accessibility** (called **Device Control and Data Access** on macOS 27). Both menus show **Direct Paste Enabled** once macOS grants Accessibility access; the menu labels, row actions, and Return hint update automatically when permission changes. Without that permission, Return copies the selected entry and returns to the previous app; press Command+V there. Copy history and the global shortcut do not require Accessibility access. The app never requests permission at startup.

If ^V is already enabled in System Settings but the app still shows **Enable Direct Paste…**, remove the old ^V entry with the minus button, add the current app from Applications, and enable it again. **Enable Direct Paste…** opens help showing the exact path of the running app. This can happen after rebuilding an ad-hoc-signed version or switching signing identities. It requires one fresh grant when migrating to a development-signed build. macOS tracks permission by the app’s code identity, not just its displayed name; see [Apple’s explanation of designated requirements](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements).

## Storage and performance

- Keeps up to 200 items, 32 MiB of payloads, and 30 pins. Individual copies over 4 MiB are skipped.
- Preserves plain text, RTF, HTML, PNG/TIFF images, URLs, and file URLs, including multiple files. Files are referenced, not duplicated; moved/deleted files can no longer be pasted reliably.
- History is local at `~/Library/Application Support/ctrlv/history.json`, with owner-only directory/file permissions. It is not encrypted. There is no network code, account, analytics, or cloud sync.
- Ignores clipboard content explicitly marked concealed, transient, or autogenerated. Apps that do not mark sensitive copies cannot be detected reliably; pause capture when needed.
- Deduplicates exact clipboard representations and preserves pins. Search indexes the first 10,000 characters of text; the complete payload is retained within the size limit.
- Checks the pasteboard change counter every 450 ms with 150 ms timer tolerance. Reads payloads only on changes; disk writes and image thumbnail generation run off the main thread. Extremely brief intermediate clipboard changes can be missed by polling.
- Pinning protects entries from normal eviction. Clear history keeps pinned entries and leaves the system clipboard unchanged.
- Ad-hoc and Apple Development signing are for local use. Distribution requires Developer ID signing and notarization. Rebuilding an ad-hoc-signed app or changing its signing identity may require re-adding its Accessibility permission.

## Native design

Pane map: **focused search → continuous history list → keyboard hints**, inside one resizable floating `NSPanel` (390 × 510 pt by default; 340 × 350 pt minimum). `NSGlassEffectView` is the single transient surface, not an inner decorative shell. Rows use native list selection with no per-row glass. Semantic colors follow the system appearance; Reduce Transparency supplies a stable background. Search is a borderless native `NSTextField` for text editing, focus, and input method support. Marked text keeps control of Return and arrow keys.

The AppKit bridge exists for nonactivating panel focus, global hotkeys, pasteboard access, and returning to the previous application. SwiftUI owns content and observable history state. Source files are split by model, store, service, view, and app lifecycle.

Apple references: [NSGlassEffectView](https://developer.apple.com/documentation/appkit/nsglasseffectview), [Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/liquid-glass), and [NSPasteboard changeCount](https://developer.apple.com/documentation/appkit/nspasteboard/changecount). No Figma node was supplied or inspected. The app uses macOS 26+ public APIs and inherits system rendering on macOS 27.

## Verification

All 14 automated tests pass, covering exact deduplication, pin retention, eviction, memory limits, multiword/accent search, concealed content exclusion, rich-text/image/multi-file round trips, oversized-copy rejection, suppression of self-capture, pause/resume, persistence permissions, observable direct-paste permission grant/revocation, rechecking permission before paste, and cancelling a pending paste. Clipboard tests use unique pasteboards and temporary storage; permission tests inject access checks without changing system grants or posting keys.

Live checks verified launch, default and reopened search focus, text/link capture, filtering and empty results, arrow selection, pinning, and copying a selected item into TextEdit. The release bundle measured about 648 KiB. Global hotkey registration succeeded; targeted automation key events bypass global routing, so physical Control+V still needs a manual check. Direct paste requires user-granted Accessibility access and was not tested without it. Light/dark variants, full VoiceOver traversal, system glass tint, and accessibility display preferences need further manual checks.
